# Подключение тестового Telegram

Первый шаг — определить закрытую группу для @dubai_housing_test_alalni_bot.
Ручная отправка одной проверенной карточки жилья реализована отдельным workflow.
Обработка диалогов ещё не подключена.

1. Добавьте бота в закрытую группу без тем. Достаточно обычного участника с правом писать сообщения.
2. Сохраните токен как GitHub Actions secret `TEST_TELEGRAM_HOUSING_BOT_TOKEN`.
3. В самой группе отправьте `/setup@dubai_housing_test_alalni_bot`.
4. Откройте Actions → **Telegram setup (test)** → Run workflow → **develop**.
5. В Summary успешного запуска скопируйте числовой ID вместе с минусом и сохраните как secret `TEST_TELEGRAM_CHAT_ID`.

Бот на команду пока не отвечает. Команда нужна для определения группы через
[getUpdates](https://core.telegram.org/bots/api#getupdates); Telegram хранит обновления не дольше 24 часов.
Privacy Mode можно оставить включённым: команда адресована боту явно.
Если обновлений нет, отправьте команду заново и повторите запуск.

Настройка проверяет точный username токена, отсутствие webhook и единственную подходящую
группу. Публичные группы, личные сообщения и группы с темами не принимаются.
Несколько групп с командой за последние сутки или полная очередь из 100 обновлений
требуют отдельного разбора; скрипт не очищает очередь и не отключает webhook.
Не запускайте параллельно другой процесс, читающий обновления этого бота.

В Summary публикуются только username бота и ID группы. Summary доступен читателям
публичного репозитория; название группы, сообщения, участники и токен не выводятся.
ID не даёт доступа к закрытой группе. Сохранение ID в secret выполняет владелец вручную;
скрипт сам не привязывает группу для отправки.

Workflow регистрируется в `main`, но выполняется только на `develop`. Настройка
не обращается к OpenAI или DeepSeek, ничего не отправляет в Telegram и не использует production.

## Отправить карточку жилья

1. Запустите **Search Dubai (test)** на `develop` с ролью `housing`.
2. В артефакте поиска откройте `drafts.md`, проверьте текст и исходную ссылку.
   Выберите карточку со статусом `needs_review`. `blocked` отправить нельзя.
3. Скопируйте **ID карточки** из `drafts.md` (в старом отчёте это `material.id` в `report.json`).
4. Откройте **Telegram send housing (test)** → Run workflow → `develop`.
   Укажите `search_run_id` — число из URL успешного поиска после `/actions/runs/`,
   и `draft_id` — ID выбранной карточки. Включите `confirm_reviewed` после проверки.
5. Запуск отправит ровно одну карточку в группу из `TEST_TELEGRAM_CHAT_ID`.

Отправка не вызывает OpenAI или DeepSeek и не меняет текст. Допускается только
артефакт успешного ручного поиска на `develop` в этом репозитории. Карточка должна
пройти все четыре проверки фактов без замечаний. Через час после проверки источника
или по `expires_at` (что наступит раньше) она устаревает: нужен новый поиск.

## Повторы и сбои

До `sendMessage` workflow атомарно создаёт файл `.delivery/test/<hash>.json`
в ветке `develop` через GitHub Contents API. Поэтому ему нужен `contents: write`.
В файле только статус, время и хеш текста; нет токена, chat ID, переписки или участников.
Ключ учитывает бота, группу и `discovery_key` предложения. Карточка с тем же ключом
не отправляется заново, в том числе после редактуры текста. Новый поиск может
создать другой ключ при изменении данных, формулировок источника или числа
сравниваемых предложений: смысловые повторы пока проверяет редактор вручную.

Статус `reserved` означает, что попытка занята, но её исход может быть неизвестен.
При тайм-ауте Telegram, остановке workflow или ошибке записи результата повтор
останавливается. Сначала проверьте группу и журнал. Автоматического снятия
резервирования нет. Не удаляйте журнал ради повторного запуска без проверки группы.
Статус `sent` записывается после подтверждения Telegram.

Workflow зарегистрирован в `main` только для появления кнопки Actions; отправка
доступна на `develop` по ручному подтверждению. Автопубликация, расписание,
production и диалоги остаются отдельными этапами.

API: [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage),
[GitHub Contents](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents).
