# Подключение тестового Telegram

## Быстрый тест: один запуск

Запустите **Search Dubai (test)** на `develop`, оставив `send_to_test` включённым.
По умолчанию выбраны жильё и запрос недорогих вариантов. Роль и запрос можно менять.
После поиска бот сразу присылает один тестовый отчёт в закрытую группу: первую
карточку, а при отсутствии карточек — причины отклонения. ID копировать не нужно.
Для тестов всех ролей временно используется имеющийся бот «Жильё»; роль указана в сообщении.

Заблокированный исходный черновик тоже показывается, с явной пометкой
«НЕ ПРОШЛА ПРОВЕРКУ» и замечаниями. Это диагностический просмотр, статус карточки
остаётся `blocked`. Длинный текст сокращается с пометкой; полный отчёт — в артефакте.
Если сам API-поиск завершился ошибкой до создания отчёта, причина видна в Actions.
Повтор того же запуска не отправит сообщение ещё раз; новый Run workflow создаёт
новый тест. Для этого используется тот же журнал резервирования `.delivery/test`.

Строгая ручная отправка ниже остаётся дополнительным режимом. Автоматическая
публикация в production отключена.

Первый шаг — определить закрытую группу для @dubai_housing_test_alalni_bot.
Ручная отправка одной проверенной карточки жилья реализована отдельным workflow.
Обработка диалогов ещё не подключена.

1. Добавьте бота в закрытую группу без тем. Достаточно обычного участника с правом писать сообщения.
2. Сохраните токен как GitHub Actions secret `TEST_TELEGRAM_HOUSING_BOT_TOKEN`.
3. В самой группе отправьте `/setup@dubai_housing_test_alalni_bot`.
4. Откройте Actions → **Telegram setup (test)** → Run workflow → **develop**.
5. В Summary успешного запуска скопируйте числовой ID вместе с минусом и сохраните как secret `TEST_TELEGRAM_CHAT_ID`.

Бот на команду пока не отвечает. Команда нужна для определения группы через
[getUpdates](https://core.telegram.org/bots/api#getupdates); Telegram хранит обновления не дольше 24 часов.
Privacy Mode можно оставить включённым: команда адресована боту явно.
Если обновлений нет, отправьте команду заново и повторите запуск.

Настройка проверяет точный username токена, отсутствие webhook и единственную подходящую
группу. Публичные группы, личные сообщения и группы с темами не принимаются.
Несколько групп с командой за последние сутки или полная очередь из 100 обновлений
требуют отдельного разбора; скрипт не очищает очередь и не отключает webhook.
Не запускайте параллельно другой процесс, читающий обновления этого бота.

В Summary публикуются только username бота и ID группы. Summary доступен читателям
публичного репозитория; название группы, сообщения, участники и токен не выводятся.
ID не даёт доступа к закрытой группе. Сохранение ID в secret выполняет владелец вручную;
скрипт сам не привязывает группу для отправки.

Workflow регистрируется в `main`, но выполняется только на `develop`. Настройка
не обращается к OpenAI или DeepSeek, ничего не отправляет в Telegram и не использует production.

## Отправить карточку жилья

1. Запустите **Search Dubai (test)** на `develop` с ролью `housing`.
2. В артефакте поиска откройте `drafts.md`, проверьте текст и исходную ссылку.
   Выберите карточку со статусом `needs_review`. `blocked` отправить нельзя.
3. Скопируйте **ID карточки** из `drafts.md` (в старом отчёте это `material.id` в `report.json`).
4. Откройте **Telegram send housing (test)** → Run workflow → `develop`.
   Укажите `search_run_id` — число из URL успешного поиска после `/actions/runs/`,
   и `draft_id` — ID выбранной карточки. Включите `confirm_reviewed` после проверки.
5. Запуск отправит ровно одну карточку в группу из `TEST_TELEGRAM_CHAT_ID`.

Отправка не вызывает OpenAI или DeepSeek и не меняет текст. Допускается только
артефакт успешного ручного поиска на `develop` в этом репозитории. Карточка должна
пройти все четыре проверки фактов без замечаний. Через час после проверки источника
или по `expires_at` (что наступит раньше) она устаревает: нужен новый поиск.

## Повторы и сбои

До `sendMessage` workflow атомарно создаёт файл `.delivery/test/<hash>.json`
в ветке `develop` через GitHub Contents API. Поэтому ему нужен `contents: write`.
В файле только статус, время и хеш текста; нет токена, chat ID, переписки или участников.
Ключ учитывает бота, группу и `discovery_key` предложения. Карточка с тем же ключом
не отправляется заново, в том числе после редактуры текста. Новый поиск может
создать другой ключ при изменении данных, формулировок источника или числа
сравниваемых предложений: смысловые повторы пока проверяет редактор вручную.

Статус `reserved` означает, что попытка занята, но её исход может быть неизвестен.
При тайм-ауте Telegram, остановке workflow или ошибке записи результата повтор
останавливается. Сначала проверьте группу и журнал. Автоматического снятия
резервирования нет. Не удаляйте журнал ради повторного запуска без проверки группы.
Статус `sent` записывается после подтверждения Telegram.

Workflow зарегистрирован в `main` только для появления кнопки Actions; отправка
доступна на `develop` по ручному подтверждению. Автопубликация, расписание,
production остаются отдельными этапами.

## Третья реплика в тесте с Мирой

После ответа `@mira` на отправленный вопрос о погоде запустите
**Telegram reply to Mira (test)** из `develop`. Он читает доступный ответ
из Telegram. По умолчанию включён `diagnostic_only`: сообщения не отправляются,
в журнале шага появляются строки `MIRA_DIAGNOSTIC` с количеством обновлений,
сообщений нужной группы, ответов от `@mira`, сообщений через `via_bot` и причинами
отклонения. Имена других участников, ID, текст переписки и адрес webhook не выводятся.
Ноль обновлений не доказывает конкретную причину: ответ мог не доставляться боту,
истечь или быть забран другим процессом. `via_mira_messages` позволяет отличить
сообщения через Миру от сообщений, у которых она указана отправителем; фильтр
отправителя автоматически не ослабляется. Для отправки снимите `diagnostic_only`.
В этом режиме Actions читает доступный ответ
из Telegram и отправляет одну короткую завершающую реплику «Жилья» с привязкой
к сообщению Миры. Приветствие повторно запускать не нужно.

Это ограниченный тест: вопрос «Жилья» → ответ Миры → заключение «Жилья».
Заключение выбирается по тексту ответа из коротких шаблонов, без OpenAI/DeepSeek,
новых погодных утверждений или выполнения инструкций из переписки.
Защита журнала не позволяет повторить заключение даже при новом запуске Actions.
Дальнейшие сообщения Миры этот тест не обрабатывает. Остановку самой Миры после
третьего сообщения нужно настроить отдельно на её стороне; её код здесь отсутствует.

Запуск читает очередь один раз, без постоянного слушателя и без удаления обновлений.
Если ответ не найден, ничего не отправляется. Telegram хранит обновления не более
24 часов; уже забранный другим процессом ответ также может быть недоступен.
Активный webhook, переполненная очередь или несколько подходящих ответов
останавливают тест. Переписка и данные участников не сохраняются в репозиторий.
Для получения сообщений другого бота может потребоваться Bot-to-Bot Communication
Mode: [правила Telegram](https://core.telegram.org/api/bots/bot-to-bot).

API: [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage),
[GitHub Contents](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents).

## Свободный разговор с Мирой: один эксперимент

Запустите **Telegram free dialogue (test)** → **Run workflow → develop**.
Нужны существующие секреты `TEST_OPENAI_API_KEY`, `TEST_TELEGRAM_HOUSING_BOT_TOKEN`
и `TEST_TELEGRAM_CHAT_ID`. Новых полей и ключей нет. OpenAI (`gpt-4.1-mini`)
сгенерирует первую реплику на свободную тему и до четырёх ответов на реальные
сообщения `@mira`. Каждый ответ привязан к сообщению собеседницы.

Лимит — пять вызовов OpenAI, максимум 400 выходных токенов на вызов и пять
реплик «Жилья». Поиск в интернете не вызывается. На пятой реплике бот завершает
разговор и больше не читает ответы. Мира управляется отдельно и может ответить
ещё раз: общий лимит сообщений обеих сторон не гарантируется.

Ожидание ответа — до 90 секунд, общий срок — до 8 минут (сам Actions до 12 минут).
Если Мира молчит, ответ неоднозначен, очередь полна или API вернул ошибку,
эксперимент останавливается без автоматических повторов. Сообщения других
участников и ответы из прошлых бесед в контекст OpenAI не попадают.
Контекст текущего разговора передаётся OpenAI с `store: false`. В журнале лишь
статусы, счётчики, время и хеши отправленных реплик.

В разделе Artifacts запуска сохраняется `mira-dialogue-<run_id>-<attempt>`
на 7 дней: `dialogue.md` для чтения и `dialogue.jsonl` для анализа. Реплики
записываются сразу после подтверждённой отправки или получения ответа Миры,
поэтому при ошибке остаётся частичный разговор. Шаг загрузки выполняется и при
сбое; при принудительной остановке runner загрузка не гарантируется.
Полный штатный файл содержит 9 реплик: 5 от «Жилья» и 4 полученных от Миры.
Возможный ответ Миры на пятую реплику не читается и в артефакт не входит.
Файлы содержат только текст, имя роли и время, без Telegram ID и секретов;
известные значения секретов дополнительно маскируются. Переписка не коммитится
в репозиторий. Артефакт доступен пользователям с правом скачивания артефактов
этого репозитория; это не приватное хранилище Telegram.
Старые запуски без этой функции артефакта диалога не имеют.

Это один согласованный эксперимент: постоянная запись в журнале создаётся
до первого платного запроса. **Повторный Run workflow или Re-run не начинают
новый разговор и не восстанавливают оборванный**, чтобы не превысить бюджет
пяти вызовов. Для следующего эксперимента нужно отдельно согласовать новый запуск
и идентификатор; удалять записи журнала ради повторения не нужно.

## Интервью о сделках Миры и оценка ответов

Отдельный согласованный тест: **Telegram trading review with Mira (test)** →
**Run workflow → develop**. Использует те же три тестовых секрета и ту же
закрытую группу. Отправитель — «Жильё», ответы генерирует OpenAI.
До четырёх вопросов по реальным ответам Миры, пятая реплика — итоговая оценка.
Всего не более пяти вызовов OpenAI и пяти отправок; новый сценарий имеет свой
фиксированный журнал, а лимит уже завершённого свободного разговора не сбрасывается.

OpenAI спрашивает, были ли реальные сделки, за какой период, как посчитан результат
после расходов, что относится к закрытым позициям и что остаётся нереализованным.
Уточнения зависят от ответов: например, не приняты ли пополнения за прибыль,
есть ли данные о капитале, комиссиях и просадке. Если Мира не торговала или
не имеет данных, модель должна принять это, не требовать выдуманных результатов.

Итог оценивает полноту и согласованность **заявлений**, а не подтверждает
эффективность торговли. Ко всему итоговому тексту программно добавляется
оговорка об отсутствии независимой проверки сделок. Доступа к кошельку,
подписанию, переводам, рынку или поиску нет. Ссылки из ответов не открываются.
Секреты и подключение кошелька не запрашиваются; торговые рекомендации запрещены
инструкциями модели. Это ограничения промпта, а не гарантия безошибочности модели.

Артефакт `mira-trading-review-<run_id>-<attempt>` содержит `dialogue.md` и
`dialogue.jsonl`, включая пятую итоговую реплику, и хранится 7 дней.
При молчании Миры или ошибке API сохраняется частичный диалог без обещания
итоговой оценки. Повторный запуск не создаёт новые платные запросы.
