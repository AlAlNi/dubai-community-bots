# Подготовка черновиков

## Быстрый запуск

Нужен Node.js 22 или новее. Зависимости и API-ключи не нужны. Все команды запускаются из корня репозитория.

```sh
node src/cli.js --demo
node --test
```

Демо использует фиксированное время 26 сентября 2026 года, 08:00 в Дубае. Четыре вымышленных материала превращаются в черновики, пятый отклоняется как устаревший. Источники example.com — заглушки. Это демонстрация обработки данных, а не реальные рекомендации о Дубае.

Результат сохраняется в `data/demo-report.json` и выводится в терминал. При повторном запуске новые копии тех же черновиков не создаются. Поле `added` показывает количество новых черновиков, `duplicates` — идентификаторы повторов, `rejected` — причины отклонения. Массив `drafts` хранит все ранее подготовленные черновики вместе с исходными фактами.

## Свои материалы

Создайте JSON-массив по образцу `examples/materials.json`, заменив вымышленные данные проверенными фактами:

```sh
node src/cli.js --input materials.json --output data/report.json
```

В этом режиме используется текущее время компьютера. Обязательные поля:

| Поле | Содержание |
| --- | --- |
| `id` | Ваш идентификатор материала |
| `role` | `guide`, `events`, `transport`, `everyday` |
| `topic` | Тема; например, `places`, `events`, `transport`, `services`, `immigration` |
| `title` | Короткий заголовок |
| `facts` | Непустой массив проверенных фактов на русском языке |
| `source_name`, `source_url` | Название источника и HTTPS-ссылка |
| `checked_at` | Когда редактор проверил источник |
| `expires_at` | Когда материал перестаёт быть актуальным |
| `event_at`, `location`, `conditions` | Для роли `events`: начало, место, условия посещения |

Даты указываются с часовым поясом, например `2026-09-26T18:00:00+04:00`. Для неизвестных условий события можно явно написать «Организатор не указал; уточните по ссылке». Не подставляйте вымышленные значения.

Давность проверки задаётся `max_source_age_hours` в `config/editorial.json`; исходное значение — 48 часов. Проверка дат использует переданные метаданные. Прототип не открывает ссылки и не подтверждает достоверность самих фактов.

## Генерация и повторная обработка

Тексты собираются по четырём шаблонам без языковой модели. Факты сохраняются дословно; оформление события использует часовой пояс Дубая. Все результаты имеют статус `needs_review`, а чувствительные темы дополнительно получают `review_reason: sensitive_topic`.

Повторы определяются по нормализованной ссылке, роли, теме и содержимому. Метки UTM и фрагмент ссылки не учитываются. Изменение фактов создаёт новую версию. Семантически похожие тексты с разных сайтов автоматически не объединяются.

На новом запуске просроченные черновики помечаются `expired`. Отчёт является одновременно результатом и историей обработки; для независимого эксперимента выберите другой `--output`. Демо и реальные материалы должны использовать разные отчёты.

Результат записывается через временный файл с заменой итогового отчёта. Файл `.lock` предотвращает одновременную запись двух процессов. После аварийного завершения ОС может оставить `.lock`: удаляйте его только после проверки, что другой процесс не работает. Повреждённый отчёт не перезаписывается.

## Границы прототипа

Поддерживается локальный JSON-источник. Автоматический сбор сайтов, RSS, языковая модель, расписание и отправка в Telegram ещё не реализованы. Настройки лимитов и окна публикаций предназначены для будущего планировщика; к подготовке черновиков они пока не применяются. Чат и аккаунты ботов для запуска не нужны.
