# Поиск источников и подготовка постов

Интеграция находится в `develop`. Поиск работает только в окружении `test` и не отправляет сообщения в Telegram. Первый [живой запуск OpenAI](https://github.com/AlAlNi/dubai-community-bots/actions/runs/36227659504) завершился успешно. Редактура DeepSeek пока проверена только на подставных ответах; локальные тесты не расходуют баланс.

## Запуск через GitHub Actions

1. В Settings → Secrets and variables → Actions → New repository secret добавьте `TEST_OPENAI_API_KEY`. Значение — API-ключ проекта OpenAI.
2. Откройте Actions → **Search Dubai (test)** → **Run workflow**.
3. В списке веток выберите **develop**. Укажите тему, роль бота и период 1–14 дней.
4. Для редактуры добавьте отдельный secret `TEST_DEEPSEEK_API_KEY` и включите `use_deepseek`. По умолчанию опция выключена. Запуск выполняет тесты, затем до двух запросов поиска; с редактурой — ещё до двух запросов на каждый новый пост.
5. На странице завершённого запуска скачайте архив **dubai-search-test-N** из Artifacts. Откройте `drafts.md` для чтения постов и `report.json` для статусов и причин отбраковки.

Служебный workflow присутствует также в `main`, чтобы GitHub показывал ручной запуск. Условие job разрешает выполнение только для `develop`; выбор `main` приводит к пропуску job. Это не выпуск кода поиска в рабочее окружение.

Workflow не запускается по расписанию, при push или PR. Ключ передаётся только шагу поиска. Тексты и исследования находятся в артефакте, который хранится 7 дней. Репозиторий публичный: используйте в темах только сведения, допустимые для публичного проекта, без личных данных участников.

**Ограничение текущего Actions-запуска:** каждый runner начинает с пустой историей. Дедупликация и дневной счётчик между разными Actions-запусками пока не сохраняются. Ограничения числа запросов, вызовов поиска и выходных токенов действуют на каждый запуск. До регулярной работы потребуется постоянное хранилище истории. Для локальных запусков история уже сохраняется между перезапусками.

## Локальный запуск

Нужен Node.js 22+. Зависимостей нет. В корне репозитория создайте игнорируемый Git файл `.env`:

```dotenv
TEST_OPENAI_API_KEY=ваш_ключ
```

Переменная `OPENAI_API_KEY` не используется: тестовый процесс читает только `TEST_OPENAI_API_KEY`. Значение из окружения процесса имеет приоритет над `.env`.

```sh
node src/search-cli.js --query "События в Дубае на ближайшие выходные" --role events --days 7
```

Для просмотра параметров запроса без ключа и расходов:

```sh
node src/search-cli.js --query "Изменения движения в Дубае" --role transport --days 3 --dry-run
node --test
```

Роли: `guide`, `events`, `transport`, `everyday`. По умолчанию — `guide`, период — 7 дней. `--env production` запрещён на этом этапе.

## Что происходит

1. Responses API вызывает `web_search` с доступом к интернету и ищет актуальную информацию о Дубае. Темы и даты передаются в запросе, списка разрешённых сайтов нет.
2. Сохраняются текст исследования, цитирования API, найденные источники, ID ответа и usage.
3. Второй запрос без инструментов извлекает материалы в строгом JSON-формате. Каждому факту соответствует фрагмент исследования, на который опирается пересказ.
4. Программа проверяет, что ссылка присутствует в цитированиях, а фрагмент действительно содержится в исследовании. События без времени, вне периода поиска и истёкшие материалы отклоняются.
5. Программа готовит черновики. Каждый получает `needs_review`; служебная пометка о проверке хранится отдельно от текста поста.

## Редактура DeepSeek

Локально добавьте `TEST_DEEPSEEK_API_KEY` в `.env` и передайте `--style deepseek`. Нужны оба ключа; отсутствие ключа редактора останавливает запуск до платного поиска.

DeepSeek получает только исходные факты и пишет основной абзац с учётом роли бота. Заголовок, дата, место, условия и ссылка добавляются кодом. Новые числовые значения, ссылки и превышение длины отклоняются. Затем отдельный запрос OpenAI без поиска проверяет весь пост на добавленные утверждения и потерянные факты. При отрицательном результате, сомнении, неполном ответе или ошибке API сохраняется исходный текст. Повторных попыток нет.

В `report.json` поле `original_text` сохраняет исходный пост, `style.status` показывает `accepted` или `fallback`, а `style.reason` — причину. `accepted` означает только прохождение автоматической сверки; статус поста остаётся `needs_review`. Отклонённый вариант не сохраняется как альтернативный готовый пост.

Настройки в `config/style.json`: редактор `deepseek-flash`, проверяющий `gpt-5-mini`, тайм-аут 45 секунд на каждый запрос. DeepSeek получает факты выбранного материала, поэтому не добавляйте туда приватную переписку. Автоматическая сверка может пропустить ошибку и не исправляет ошибку исходного источника.

Такая проверка связывает текст с исследованием, но не доказывает истинность фактов или соответствие исходной веб-странице. До одобрения редактор открывает ссылки и сверяет даты, цены, условия и формулировки. `research_excerpt` — фрагмент ответа модели, а не дословная цитата сайта. `checked_at` у этих материалов означает время поиска, не ручную проверку.

## Файлы результата

Все данные находятся в `data/test/search/` и исключены из Git:

- `drafts.md` — читаемая подборка активных черновиков.
- `report.json` — черновики с исходными фактами, статусами и причинами отклонения.
- `runs.json` — журнал зарезервированных, успешных и неуспешных запусков.
- `<идентификатор>.json` — исследование, ссылки, материалы и сведения о расходе токенов конкретного запуска.

Один источник, роль и время события дают один активный материал, даже если модель поменяла заголовок. Это консервативная дедупликация: изменения на той же странице могут быть пропущены до истечения старого черновика. Разные страницы об одном событии могут требовать ручного объединения.

## Лимиты и ошибки

Настройки — `config/search.json`: модель `gpt-5-mini`, максимум 3 материала, 3 вызова web search, до 6000 выходных токенов на запрос поиска/извлечения, тайм-аут 90 секунд. Без редактуры запуск делает не более двух запросов. При отсутствии цитирований второй запрос пропускается. С DeepSeek при трёх новых постах — до восьми запросов суммарно: два поиска/извлечения, три редактуры, три сверки. Старые черновики повторно не редактируются.

В постоянном локальном хранилище разрешено 6 запусков за сутки по Дубаю. Слот резервируется до обращения к API; ошибки тоже занимают слот. Это ограничение объёма работы, не гарантированный лимит в валюте: расходы зависят от входных токенов, поискового контекста и тарифов API.

Ошибки 401/403, 429, сетевые сбои и неполные ответы не приводят к автоматическому повтору. При тайм-ауте запрос мог выполниться на стороне провайдера. Неудачный повтор не уничтожает предыдущий отчёт, а уже полученное исследование сохраняется. Файл `.lock` запрещает одновременную запись; после аварии удаляйте его только убедившись, что процесс завершён.
