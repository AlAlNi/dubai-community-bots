# Порядок разработки

Этот документ задаёт текущий порядок работ. Каждый этап сначала проверяется в `develop`. Следующий этап начинаем после выполнения критериев текущего.

| Этап | Результат | Статус |
| --- | --- | --- |
| 0. Локальные черновики | JSON → проверка → четыре стиля → сохранённые черновики | Готово |
| 1. Разделение окружений | Две Git-ветки, отдельные настройки и хранилища | Реализовано в develop; чаты не подключены |
| 2. Поиск в момент подготовки | Свежие материалы через OpenAI API → проверяемый черновик со ссылками | Первый живой поиск прошёл; проверяем опциональную редактуру DeepSeek |
| 3. Закрытый Telegram-чат | Проверка и отправка постов тестовыми ботами | Запланировано |
| 4. Ответы участникам | Ответы на упоминания и реплики с контекстом конкретного диалога | Запланировано |
| 5. Диалоги ботов | Несколько тематических ботов обсуждают заданный вопрос | Запланировано |
| 6. Рабочий запуск | Проверенная версия переносится из develop в main | Запланировано |

## Два окружения

| Назначение | Git-ветка | Параметр запуска | Данные | Учётные данные |
| --- | --- | --- | --- | --- |
| Закрытый тестовый чат | `develop` | `--env test` | `data/test/` | `TEST_*` |
| Рабочий чат | `main` | `--env production` | `data/production/` | `PRODUCTION_*` |

Репозиторий остаётся публичным. Закрытым будет тестовый Telegram-чат: без публичного имени, с приглашениями только для тестеров. Приватность чата настраивается в Telegram, а не Git-веткой.

Для полной изоляции планируются два комплекта по четыре Telegram-бота и два разных chat ID. Один координатор обслуживает один комплект и один чат. Токены рабочего комплекта не передаются тестовому процессу. Значения секретов хранятся вне Git; `.env.example` содержит только имена переменных.

Сейчас окружения разделяют локальные отчёты. Поисковый CLI читает `TEST_OPENAI_API_KEY`, а при включённой редактуре — `TEST_DEEPSEEK_API_KEY` из окружения или `.env`; Telegram-токены пока не используются. Поле `delivery_enabled` должно оставаться `false`; попытка включить его завершает запуск ошибкой. [Запуск поиска через GitHub Actions](search.md).

Ветки сами по себе не выбирают чат. Будущий процесс развёртывания должен связывать `develop` с `test`, а `main` с `production`, передавая только нужный набор секретов. Перед включением отправки потребуются проверки разных chat ID и токенов, а также фактического чата назначения. Автоматическое развёртывание и защита ветки main пока не настроены.

### Запуск текущего прототипа из develop

```sh
node src/cli.js --demo --env test
node src/cli.js --input materials.json --env test
node src/cli.js --input materials.json --env production
node --test
```

Последняя команда подготовки лишь сохраняет рабочие черновики локально. `--demo --env production` запрещён. По умолчанию используется `test`. Даже при явном `--output` нельзя продолжить отчёт другого окружения. Старые отчёты без поля `environment` не перезаписываются; выберите новый путь. Папки данных и секреты не переносятся при выпуске версии.

## Этап 2. Поиск и черновики

- Запрос включает рубрику, текущую дату в Дубае и период актуальности.
- OpenAI Responses API с `web_search` находит источники по запросу. Перечень сайтов заранее не фиксируется.
- Сохраняются ссылки, подтверждаемые ими факты, даты событий и время поиска.
- Подтверждённый материал проходит проверку повторов и подготовку разговорного текста.
- Если подходящих материалов нет, тема пропускается. Расходы и число запросов ограничиваются.

Готово, когда на реальных запросах получены проверяемые черновики, а отсутствие результатов, ошибки API и повторы обработаны. До подключения Telegram результаты проверяются локально.

Первый живой поиск через Actions выполнен. Добавлена опциональная редактура DeepSeek с отдельной сверкой OpenAI и возвратом к исходному тексту; её живой запуск ещё предстоит. Между отдельными Actions-запусками история пока не сохраняется; для регулярной работы потребуется постоянное хранилище. Служебный ручной workflow регистрируется в `main`, а выполняется только из `develop`.

## Этап 3. Закрытый чат

Создать тестовую группу и тестовые аккаунты ботов. Добавить ручное одобрение, очередь отправки, журнал, лимиты и остановку. Проверить, что сообщения уходят только в тестовый chat ID и повторный запуск не дублирует отправку. Неоднозначный результат сетевого запроса требует сверки перед повтором.

## Этап 4. Ответы людям

Один координатор выбирает подходящего бота. Сначала отвечаем только на явное обращение или ответ на сообщение бота. Контекст разделяется по окружению, чату и цепочке сообщений, чтобы разговоры разных людей не смешивались. Нужны срок хранения, очистка контекста, очередь запросов и лимит расходов. При необходимости бот уточняет вопрос или выполняет свежий поиск.

Готово, когда бот корректно обрабатывает уточнения и не переносит контекст в постороннюю цепочку.

## Этап 5. Беседы ботов между собой

Координатор хранит общий контекст обсуждения и сам выбирает следующую роль. Публикация одного бота не запускает бесконечную цепочку ответов. Задача обсуждения конкретна: например, сравнить два варианта досуга с точки зрения места и транспорта.

Начальные правила:

- Запуск по команде администратора в тестовом чате.
- Не более двух ботов и четырёх реплик суммарно на обсуждение.
- Ограничения времени и бюджета; отсутствие новых полезных фактов завершает обсуждение.
- Команда остановки отменяет оставшиеся реплики.
- Каждый бот явно обозначен как бот; не выдумывает личный опыт.
- Факты подтверждаются источниками; повторение утверждения вторым ботом не считается проверкой.

Автоматический запуск таких бесед по расписанию обсуждается после проверки ручного режима.

## Этап 6. Выпуск

Изменения готовятся в `develop`, проходят тесты и проверку поведения в закрытом чате. Затем создаётся PR `develop` → `main` с описанием проверенной версии. В рабочем окружении запускается конкретный выпуск из `main` со своими секретами и пустой либо рабочей историей. Тестовая переписка и демонстрационные посты туда не копируются.

Готово, когда проверены маршрутизация в рабочий чат, остановка, лимиты, восстановление после сбоя и возврат к предыдущей версии. Новые возможности затем проходят тот же цикл через тестовый чат.
