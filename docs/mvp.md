# Первая версия

Текущий порядок этапов и статусы приведены в [едином плане разработки](roadmap.md). Этот документ описывает требования к публикациям; ответы людям и диалоги ботов добавляются отдельными последующими этапами.

## Цель

Подготовить русскоязычный Telegram-чат о Дубае с четырьмя тематическими ботами. Разработка и проверка идут в закрытом тестовом чате из ветки `develop`; проверенная версия для рабочего чата выпускается из `main`.

## Решения до реализации

- Создать тестовую Telegram-группу и назначить администратора.
- Уточнить аудиторию: жители, недавно переехавшие или туристы.
- Согласовать темы поиска, требования к источникам и бюджет внешних API и размещения.

## Этап 1. Локальный прототип

- Ввести общую модель материала: идентификатор, тема, URL, время получения, дата события, срок актуальности и факты.
- Добавить один источник и подготовку черновиков без отправки в чат.
- Хранить исходные факты отдельно от сгенерированного текста.
- Проверять повторы, истёкшие события и отсутствующие ссылки.
- Предусмотреть образцы данных для запуска без внешних ключей.

## Следующий этап. Поиск источников в момент подготовки

- На каждом запуске искать актуальные источники и материалы о Дубае через OpenAI Responses API с инструментом `web_search` и доступом к интернету.
- Формировать запросы по рубрике, текущей дате в Дубае и периоду актуальности; заранее заданный перечень сайтов не требуется.
- Отдавать приоритет официальным первоисточникам. Проверять дату события отдельно от даты публикации страницы.
- Сохранять найденные ссылки, цитирования API, время поиска и факты, подтверждённые каждой ссылкой. Одна ссылка сама по себе не подтверждает все утверждения поста.
- Передавать подтверждённые материалы в существующий конвейер черновиков. Если подходящих результатов нет, пропускать тему.
- Сохранять кликабельные ссылки на источники в итоговых постах. Учитывать повторы, ограничивать число поисковых запросов и расходы.
- После поиска готовить разговорный текст в стиле выбранного бота и отправлять черновик на проверку.

Статус: запланировано; текущий прототип пока читает локальный JSON. Поиск не гарантирует полноту или мгновенное появление всех новых публикаций.

Техническая основа: [официальная документация OpenAI по web search](https://developers.openai.com/api/docs/guides/tools-web-search).

## Этап 2. Тестовый чат

- Создать четыре Telegram-бота через BotFather и подключить их к тестовой группе.
- Добавить очередь, ручное одобрение, журнал отправок и общую остановку публикаций.
- Считать успешную отправку только после подтверждения платформы.
- Обрабатывать ограничения API; неоднозначный результат отправки проверять до повтора, чтобы не создавать дубликаты.

## Этап 3. Автоматические публикации

- Перевести проверенные рубрики на автоматическую отправку.
- Начать с общего лимита в четыре сообщения в сутки и интервала не менее 90 минут.
- Ограничить публикации окном 09:00–21:00 по Asia/Dubai.
- Пропускать публикацию, если источник недоступен или материал устарел.
- Оставить темы повышенной ответственности на ручной проверке.

## Критерии готовности

- Каждый фактический пост содержит ссылку на источник.
- Боты не добавляют неподтверждённые цены, даты, правила и личные истории.
- Один материал не публикуется повторно после перезапуска сервиса.
- Общие лимиты действуют на всех ботов вместе.
- Администратор может остановить очередь и исправить опубликованный материал.
- Ключи находятся вне репозитория; тексты участников не записываются по умолчанию.

## За пределами первой версии

Реклама, платные подписки и массовый анализ переписки участников. Ответы людям и управляемые беседы ботов включены в дальнейший план отдельными этапами после подключения тестового чата.
